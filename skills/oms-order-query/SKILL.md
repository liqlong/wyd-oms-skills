# OMS 订单多维度查询

通过已连接的 OMS MCP 服务读取当前客户的数据。常用工具是 `list_oms_queries`、
`describe_oms_query`、`query_oms`；Codex 可能给工具名称增加 MCP 服务名前缀。
工具不可用时说明连接缺失，不绕过 MCP 直接连接数据库或索取 OMS 密钥。

新任务只读订单、库存或工单信息时优先使用本Skill；创建、修改、删除、提交、取消、认领和处置走对应业务Skill。
已在入库、发货、工单或退件流程中时，可保留当前Skill按其规则查进度，不为相同查询反复切换入口。

## 选择查询

常用单据及标识明确时，按下表直接调用 `query_oms`。这些字段已与本版本查询目录核对，
不必先读取参考文件、调用 `list_oms_queries` 或重复查询参数定义；服务端仍校验所有字段及客户权限。
单号、参考号和跟踪号均传字符串，保留前导零；表中“或”表示按用户提供的标识选择一个字段。

| 用户查询 | queryName | filters |
| --- | --- | --- |
| 入库单详情/状态，按单号或参考号 | `inbound_inbound_query` | `{"inboundNo":"用户提供的标识"}` |
| ToC出库详情/状态 | `outbound_to_c_query` | `{"orderNo":"用户提供的单号"}` 或 `{"reference":"用户提供的参考号"}` |
| ToB出库详情/状态，按单号或参考号 | `outbound_tob_query` | `{"orderNo":"用户提供的标识"}` |
| 入库预约详情/状态 | `inbound_appointment_query` | `{"inboundAppointmentNo":"用户提供的预约订单号"}` 或 `{"reference":"用户提供的参考号"}` |
| 虚拟订单详情 | `outbound_virtual_query` | `{"orderNumber":"用户提供的单号"}` 或 `{"referenceNumber":"用户提供的参考号"}` |
| 退件，按退件单号、跟踪号或关联订单号 | `inbound_return_query` | `{"noStr":"用户提供的标识","pageNo":1,"pageSize":20}` |
| 未认领退件清单 | `inbound_center_query` | `{"processStatus":"0","pageNo":1,"pageSize":5}`，指定标识时另加 `noStr` |
| 当前客户所有仓库 | `common_get_all_warehouse_by_customer` | `{}` |

只查单据状态时先取结果，不额外查仓库、商品、库存、费用或图片。
状态解读按需读取 [订单查询](references/order-queries.md)；不在查询前加载整个目录。

1. 从请求中确定单据类型、标识、日期口径、SKU、状态及期望结果。保留单号和参考号的前导零。
   用户已指定“入库单”时直接查询入库单，不需要额外确认是不是预约单。
   单据类型确实不明确时，结合上下文判断；不足以判断则简短澄清。
2. 已有明确queryName时直接使用；路由未知才查 [查询目录](references/query-catalog.md)，
   或调用 `list_oms_queries` 按对应模块查看，不为已知路由获取全部52类查询。
3. 表外字段、首次使用的复杂筛选或参数含义不确定时，调用一次 `describe_oms_query`。
   同一会话复用已取得的schema，翻页及重复查询不再获取；切换MCP服务或服务版本变化时重新核对。
   不猜测字段或枚举；无参数查询使用 `filters: {}`。
4. 使用 `query_oms(queryName, filters)` 执行。业务信息缺失时只询问影响本次查询的内容。
   列表查询可以只有时间、SKU或状态，不要求一定提供单号。
   快速查询遇到未知类型或参数校验失败时，获取实时schema并按原意修正，最多再查一次；
   `EMPTY` 不换接口反复查，HTTP、认证或OMS业务错误也不自动换条件重试。

## 参数与业务口径

- 不猜测订单号、参考号、SKU、仓库代码、平台代码、状态码或时间范围。
  仓库名称可以先查公共仓库列表，匹配真实代码；有多个匹配时再澄清。
- `orderNo`、`reference` 等单据字段必须是字符串。字符串状态码不能写成 JSON 数字。
  数组字段使用数组；逗号分隔字段按 schema 描述传字符串，不混用。
- 不同实体的同一数字状态含义可能不同。按 schema 的字段描述选择筛选码；
  解读响应时按 [订单查询](references/order-queries.md) 中对应实体和字段的映射。
  筛选枚举与响应状态分别处理，不能因为响应出现某个状态就把它传入筛选条件。
  未列出的状态保留原值，不套用 ToC 状态映射。
- 日期按 `datePattern` 或字段描述传入；毫秒时间戳字段使用 JSON 整数。
  “最近7天”等相对时间先确定当前日期和业务时区；创建、提交、发货、ETA 等口径不明确且影响结果时先澄清。
  列表日期格式为 `yyyy-MM-dd` 时不要自行追加时分秒；只传筛选日期，不手工加减 OMS 的时区偏移。
- 当前客户范围由 MCP 请求认证决定，不传 `dataBelong`、客户代码集合或凭据。
  没有某个过滤维度时说明接口限制；需要在结果中筛选时，注明仅对已取回数据进行筛选。

## 分页与结果

- 默认第一页、每页20条。查询工具一次只返回一页，沿用原过滤条件翻页；
  页码字段可能是 `pageNo`、`pageNum` 或 `current`，长度字段可能是 `pageSize` 或 `size`。
  以 schema 为准，不超过其 `maximum`。
- 只需要列表预览时，结果下方主动说明本页实际条数、当前页/总页数、总条数及是否还有下一页。
  有下一页时明确提示“还有下一页，可以说‘下一页’继续查看”；末页说明“已到最后一页”。
  例如：“本页20条，共65条，当前第1/4页，还有45条未展示。可以说‘下一页’继续查看。”
  数字必须根据实际分页回执计算。总数或总页数未返回时省略未知数字；不能仅凭满页断言还有下一页，
  应说明“接口未返回完整分页信息，是否还有下一页尚未确认，可以说‘下一页’尝试继续查询”。
  用户要求全部或统计时，根据实际响应的页码、页大小、总数逐页读取。
  默认每轮最多读取10页，分批说明进度后继续读取，不逐页要求用户说“下一页”或再次授权。
  因错误或执行限制未读完时，说明已读范围、未读数量（可确定时）及如何继续，不能将当前批次当作全部结果。
  空页、达到总页数、重复页面、权限错误或超时应停止，避免无限翻页。
- 订单详情可能在一个返回对象里包含独立分页的 SKU、预报或实收信息。
  主单状态已查到不代表明细已完整读取；按用户需求继续查详情页。
- 按 OMS 实际响应展示结果：`SUCCESS` 展示查到的数据，`EMPTY` 提示“按本次条件未查到数据”，
  `ERROR` 展示接口返回的错误信息。保留原始状态和分页信息，不额外推断上游原因。
- 简洁展示查询条件、单据号、参考号、状态、仓库和相关时间。
  最小回执为“查询条件/范围 + 实际结果 + 完整性和分页提示”，具体排版按用户需要，
  不为补齐格式猜测单号、时间、总数或状态。未读取的明细、页面或关联信息明确说明。
  原始状态码可与中文含义并列。只展示用户需要的收件信息，不在普通订单列表附带电话或完整地址。
- 区分接口返回事实、统计结果和推断。列表有多条匹配时展示候选，不擅自挑一条。
  汇总时注明查询时间、日期口径及读取是否完整。
- 只执行查询工具。查询到异常可以说明现状，不因为用户问“为何没发货”而自动截单、建工单或改单。
