# OMS 订单多维度查询

通过已连接的 OMS MCP 服务读取当前客户的数据。常用工具是 `list_oms_queries`、
`describe_oms_query`、`query_oms`；Codex 可能给工具名称增加 MCP 服务名前缀。
工具不可用时说明连接缺失，不绕过 MCP 直接连接数据库或索取 OMS 密钥。

## 选择查询

1. 从请求中确定单据类型、标识、日期口径、SKU、状态及期望结果。保留单号和参考号的前导零。
   用户已指定“入库单”时直接查询入库单，不需要额外确认是不是预约单。
   单据类型确实不明确时，结合上下文判断；不足以判断则简短澄清。
2. 常用路由及示例见 [订单查询](references/order-queries.md)。其余能力见
   [查询目录](references/query-catalog.md)，或调用 `list_oms_queries` 按模块查看。
3. 每次会话首次使用一个查询类型前调用 `describe_oms_query`，读取 `inputSchema`。
   只传 schema 允许的字段；无参数查询使用 `filters: {}`。
4. 使用 `query_oms(queryName, filters)` 执行。业务信息缺失时只询问影响本次查询的内容。
   列表查询可以只有时间、SKU或状态，不要求一定提供单号。

## 参数与业务口径

- 不猜测订单号、参考号、SKU、仓库代码、平台代码、状态码或时间范围。
  仓库名称可以先查公共仓库列表，匹配真实代码；有多个匹配时再澄清。
- `orderNo`、`reference` 等单据字段必须是字符串。字符串状态码不能写成 JSON 数字。
  数组字段使用数组；逗号分隔字段按 schema 描述传字符串，不混用。
- 不同实体的同一数字状态含义可能不同。按 schema 的字段描述选择筛选码；
  解读响应时按 [订单查询](references/order-queries.md) 中对应实体和字段的映射。
  筛选枚举与响应状态分别处理，不能因为响应出现某个状态就把它传入筛选条件。
  未列出的状态保留原值，不套用 ToC 状态映射。
- 日期按 `datePattern` 或字段描述传入；毫秒时间戳字段使用 JSON 整数。
  “最近7天”等相对时间先确定当前日期和业务时区；创建、提交、发货、ETA 等口径不明确且影响结果时先澄清。
  列表日期格式为 `yyyy-MM-dd` 时不要自行追加时分秒；只传筛选日期，不手工加减 OMS 的时区偏移。
- 当前客户范围由 MCP 请求认证决定，不传 `dataBelong`、客户代码集合或凭据。
  没有某个过滤维度时说明接口限制；需要在结果中筛选时，注明仅对已取回数据进行筛选。

## 分页与结果

- 默认第一页、每页20条。查询工具一次只返回一页，沿用原过滤条件翻页；
  页码字段可能是 `pageNo`、`pageNum` 或 `current`，长度字段可能是 `pageSize` 或 `size`。
  以 schema 为准，不超过其 `maximum`。
- 只需要列表预览时展示当前页并说明总数和是否还有后续页。
  用户要求全部或统计时，根据实际响应的页码、页大小、总数逐页读取。
  默认每轮最多读取10页；还有数据时明确当前进度和未读数量，再继续下一批。
  空页、达到总页数、重复页面、权限错误或超时应停止，避免无限翻页。
- 订单详情可能在一个返回对象里包含独立分页的 SKU、预报或实收信息。
  主单状态已查到不代表明细已完整读取；按用户需求继续查详情页。
- 按 OMS 实际响应展示结果：`SUCCESS` 展示查到的数据，`EMPTY` 提示“按本次条件未查到数据”，
  `ERROR` 展示接口返回的错误信息。保留原始状态和分页信息，不额外推断上游原因。
- 简洁展示查询条件、单据号、参考号、状态、仓库和相关时间。
  原始状态码可与中文含义并列。只展示用户需要的收件信息，不在普通订单列表附带电话或完整地址。
- 区分接口返回事实、统计结果和推断。列表有多条匹配时展示候选，不擅自挑一条。
  汇总时注明查询时间、日期口径及读取是否完整。
- 只执行查询工具。查询到异常可以说明现状，不因为用户问“为何没发货”而自动截单、建工单或改单。
