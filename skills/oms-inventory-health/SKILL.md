# OMS 库存健康管家

使用已连接的 OMS MCP 查询工具和 `analyze_oms_inventory_health`，按用户请求生成分析。
工具缺失时提示重新连接新版 MCP。MCP 不运行定时任务、不保存或发送日报；
客户需要定时巡检或推送时，在 Agent 层另行定制脚本。

本Skill用于库存健康分析和建议。用户仅查询某SKU当前数量时使用只读库存查询，
不主动追加动销、库龄或全仓巡检；正在分析中的关联查询保持当前上下文。

## 查询范围

没有指定仓库或已提供真实仓库代码时，直接调用 `analyze_oms_inventory_health`，
不为选接口先查仓库列表或查询目录。用户要选仓、查看仓库范围或只提供仓库名称时，
用 `query_oms` 的 `common_get_all_warehouse_by_customer`、`filters: {}` 查询，不先获取空参数schema。
仓库名称匹配实际代码，不猜测。客户范围由 MCP 认证决定。

调用 `analyze_oms_inventory_health`，可传 `warehouseCode`、`sku`、`pageNo`、`pageSize`、
`salesEndDate`。库存默认第1页20条，最多100条；SKU可用逗号分隔。
默认销量窗口为包含今天在内的最近7个自然日，工具按 OMS 配置时区计算并返回实际起止日期。
用户指定截止日时使用该日期；返回 `includesCurrentDay: true` 时说明当天尚未结束。
库存是查询时的当前库存，不是历史截止日库存。

一次只分析当前库存页；根据 `inventoryPagination` 继续翻页。
只看预览时在结果下方主动说明当前库存页、本页实际条数、总数及是否还有下一页；
有后续页时提示“还有库存未分析，可以说‘下一页’继续分析”，末页说明“已到最后一页”。
分页信息不完整时省略未知数字，说明是否还有下一页尚未确认，可尝试继续；不凭满页断言有下一页。
用户要完整巡检时保留筛选条件逐页获取并说明进度，直到完成或出错，不逐页等待用户指令。
原始库存、批次和流水仍可通过 `query_oms` 查询，不绕过工具访问数据库。

## 已确定的业务规则

- 销量看包含今天在内的近7个自然日：ToC/ToB实际签出数量，减去签出回滚；
  未出库、取消、调拨、销毁等不计销量。
  流水动作为56/111签出、61/116回滚。普通退件入仓不作为签出回滚重复扣减。
  回滚多于本窗口签出时保留净出库原值，预计销量按0计算。
- 日均销量 = 近7天净销量 ÷ 7；未来7天预计销量 = 日均销量 × 7。
  补货量 = max(0, 未来7天预计销量 − 当前可用量)，向上取整到件。
  使用工具返回值，不以展示时四舍五入后的日均销量重复计算。
- 补货预留7天，用当前可用量是否够卖7天判断到仓前断货风险；不叠加成14天备货目标。
  在途、待上架、待出库、冻结和暂存分别展示，不将尚未可用的库存默认抵扣，也不重复扣减待出库。
- OMS预警沿用 `inventoryWarnStatus`、`inventoryWarnNum`；状态2为未设置，单独列出。
  库存预警和动销估算的断货风险分别展示，不能把预计销量当成OMS预警线。
- 库龄按批次库存数量分为0–29、30–59、60–89、90–179、180天及以上，互不重复。
  `unknown`表示库龄未返回。近7天无动销且存在90天以上库存时，建议评估清货或移仓。

## 展示与建议

先列需要关注的SKU和仓库，再展示可用量、在途量、预警线、近7天销量、预计可卖天数、
建议补货量、90天以上库存数量及原因。用户要求明细时展示所有库龄分层和原始库存。
回执标明实际统计窗口、当前库存页及数据完整性，再解释工具返回的计算结果；
不在对话中重新实现补货计算，也不以未读取完整的数据给出确定的补货量。
零销量时可卖天数不确定，不能将空值当成0天或无限天。

`transferCandidates`是当前库存页内的跨仓调拨候选：来源仓保留自身7天需求后的余量，
可用于目标仓缺口，工具已避免同一来源余量重复分配。它不保证实际可划拨权限和运输条件，
不按缺失的仓库容量作选仓判断。跨页或指定单仓分析时，还可按SKU查询其它仓库，
比较各仓剩余量；不要把多页候选拼接成未经核对的执行方案。
上架久的批次优先出库，清货和移仓仅提出建议，不自动执行认领、建单、调拨或销毁。

- `SUCCESS`：当前库存页及其相关统计已完成，并不代表所有库存页已读完。
- `EMPTY`：按本次条件未查到库存。
- `PARTIAL`：相关批次或流水未完整获取，查看 `salesComplete`、`batchesComplete`、
  `replenishmentComplete`。不把空计算值解释为零销量、无需补货或没有积压；
  缩小到单个仓库或SKU再查。库龄分层为已读取批次的结果，不能当作完整汇总。
- `ERROR`：展示实际错误，不据此做补货决策。
