# Codex桌面端退件图片预览

桌面对话默认使用指向本地图片的Markdown链接，用户点击后由客户端打开预览。
远程HTML `<img>` 标签、远程图片URL以及原生MCP图片内容
不能作为已向用户展示预览的依据。模型读取图片和用户看到图片是两个不同步骤。

## 生成当前批次的本地图片

1. 按Skill规则调用 `query_oms` 的 `inbound_center_query`，保留 `processStatus: "0"`、
   当前页码及默认 `pageSize: 5`。只处理这次成功查询返回的当前页记录。
2. 将工具的原始业务结果对象写入临时JSON文件，包含 `status`、`queryName` 和 `data.records`。
   不传入整个MCP外层回执，也不把附件URL或备注插入shell命令。
   使用文件写入工具或代码运行环境保存JSON；输入文件可能包含签名地址，使用权限600。
3. 从实际安装的Skill目录执行配套脚本，只需要Python 3标准库：

   ```bash
   python3 "<Skill目录>/scripts/prepare_return_previews.py" --input "<查询结果JSON路径>"
   ```

   也支持从stdin传入同一JSON。默认在系统临时目录创建独立的 `oms-return-previews-*` 私有目录，
   每单保存首张可读取的外箱图和商品图。要缓存某单全部图片，只传入该单的最新记录并加 `--all-images`。
   如需把缓存放在当前工作区，使用 `--output-dir "<缓存父目录>"`，仍会生成独立批次子目录。
4. 回执中 `orders[].previews[]` 的 `status: "CACHED"` 表示文件已写入，`localPath` 为绝对路径。
   `imageType`、`imageIndex`、`detailId`、`goodsWydSku` 保留图片与真实退件单及商品的对应关系。
   `attachmentCounts` 是全部附件数，可能包含非图片；不要把它直接称为图片总数。
   `ERROR` 的 `message` 说明本附件无法预览，保留对应原文件链接；后续成功图片仍可展示。

脚本不连接MCP或OMS，不需要Token；只读取本次查询中的文件地址，不携带业务凭据。
校验原地址和重定向的公网范围，最多3次跳转，按文件内容识别JPG、PNG、GIF、WebP，
单图最多10MiB、单次读取最多30秒，当前批次全部附件最多100个。超限时缩小查询范围。
明确的非图片扩展名不下载。读取、格式或大小失败不影响其它图片，也不执行任何认领动作。

## 在表格中提供预览链接

默认展示五单清单表格，外箱图片及商品图片列的文案均为“预览图片”。
两列分别指向该单对应类别的首张可读取图片；商品对应的SKU可在同一单元格内注明。
使用回执中实际存在的本机路径，普通Markdown链接形式为：

```markdown
| 序号 | 退件单号 | 外箱图片 | 商品图片 |
| --- | --- | --- | --- |
| 1 | RETURN-EXAMPLE | [预览图片](</实际本机目录/box.jpg>) | SKU-EXAMPLE：[预览图片](</实际本机目录/goods.png>) |
```

以上仅为语法示例；实际结果必须使用脚本生成的文件，表格及链接写入正文，不放在代码块中。
链接前不加 `!`，默认不在表格内或表格下输出缩略图。没有成功缓存的图片不生成“预览图片”链接，
显示“未返回图片”或读取失败原因，并保留原文件链接。原文件下载链接不能冒充本地预览链接。
单号或SKU中的Markdown控制字符需转义。路径含空格时保留尖括号；不用 `file://`、
`sandbox:` 或服务端路径。本地脚本运行的文件系统必须与当前Codex会话一致。

点击本地链接后的预览位置由客户端决定，不承诺在原表格行内展开图片，也不嵌入HTML事件、脚本
或 `<details>` 来模拟点击展开。客户端未能打开时说明实际情况，保留原文件链接。

查看某单全部图片时，用 `--all-images` 缓存该单图片，按外箱/商品、SKU及图片序号列出全部
“预览图片”链接。只有用户明确要求直接展开时，才按单号和SKU在正文输出
`![退件单号 外箱/商品 SKU](<本机绝对路径>)`。
需要模型读图时，使用 `view_image` 查看本机文件，或使用 `view_oms_return_image`；
工具成功仅说明模型取得了图片，不能声称用户已经查看。

展示前删除临时查询JSON；图片缓存保留供当前对话读取，不在输出正文前删除。
不将缓存加入仓库、上传到其他服务或修改图片内容。用户清理时只删除本次回执的缓存目录。
