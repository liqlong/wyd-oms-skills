# OMS 一键批量发货调度

使用 `describe_oms_outbound_operation`、`prepare_oms_outbound_batch`、
`create_oms_outbound_batch`、`cancel_oms_outbound`，查询使用现有 `describe_oms_query`、`query_oms`。
工具名称可能包含 MCP 服务前缀；缺少工具时提示连接新版服务，不自行调用 OMS 或数据库。
单笔订单使用只有一项的 `orders`，与批量订单使用相同校验和确认流程。

## 文件和聊天两种入口

- 用户上传订单表：读取 [订单表说明](references/order-sheet.md)，使用附带的离线脚本读取 XLSX/CSV，
  按序号归并多行 SKU。保留表格序号、源行号、参考号与工具调用位置的对应关系。
  脚本只整理资料，不建单；表内冲突、未知表头或不明确的枚举先核对，不能丢弃后直接发货。
- 用户在聊天中提供资料：直接整理成对应 OMS 参数对象，不要求先生成或上传表格。
  可将对话中明确适用于整批的国家、平台、仓库、物流方式等用于各单；单笔明确值优先。
  收件人地址、电话、SKU、数量、参考号不得凭空补齐。附件不是必需入口条件，用户选择自上传面单等场景时才要求对应附件。
  用户提供实际面单或ToB附件时，使用 `$oms-attachment-upload` 上传并取回真实地址；
  面单用 `SHIPPING_LABEL`，ToB附件用 `TOB_ATTACHMENT`。上传失败时先补齐附件，不用本地路径代替URL。
- 同一批混有 ToC、ToB 时按类型分组，保留原序号。整张表全部预检查通过之前不创建任何一组。
  在聊天中继续补充的资料可以用于修正表格缺项，不要求用户反复改表。

## 默认值与必填提醒

先查看 `create_oms_toc` 或 `create_oms_tob` 的实时参数定义。根据 schema、`conditionalRequirements`
和预检查返回的 `issues` 整理请求；具体口径见 [参数与查询说明](references/outbound-operations.md)。

- 已核实的 OMS 固定默认值直接采用：默认创建并提交；ToC 签名服务默认不需要；
  ToB 托盘数、贴标数未填时为 0。用户明确提供的值优先，不能用默认值覆盖用户选择。
- 库存类型未填时不传，让 OMS 使用客户配置及 OMS 默认值，不固定填为良品优先。
- ToC 发货方式、面单类型没有默认值，缺失时都先询问用户；不能默认自动分仓或系统面单。
  普通发货的快递服务、平台、仓库和渠道，以及 ToB 的出库类型、发货方式等，按实际条件补齐。
- 自动分仓匹配规则未填时先不传，让 OMS 使用客户自动分仓配置。
  若 OMS 提示规则未配置，再询问价格优先、时效优先还是先进先出，修正该失败单。
  不能为探测客户配置先建测试订单，也不能自行选择匹配规则。
- ToC 参考号1必填，没有默认值，需要用户补充。ToB 参考号非必填，缺失时询问一次；
  用户没有或不需要提供也可继续，不自动生成，不用表格序号擅自代替参考号。
- 不要求用户填写全部接口字段。把真正缺失的必填项按订单序号及中文业务名称一起提示；
  可查询得到的真实代码先查询并匹配，候选不唯一时让用户选择。
  OMS 返回新的条件必填错误时解释并补充，不猜值绕过校验。

## 选仓、选渠道和费用试算

用户另行发起已上架退件寄回时，先按其退件单号核对指定明细实际已上架（`processResult=1`），
再查询相同仓库、实际SKU的可用退件库存；上架指令成功或上架并暂存不能代替可用库存核实。
收件地址、物流方式、数量和费用由用户明确确认，不自动沿用原订单地址或自动选择退运目的地。
ToC在 `retailOrder.bizInventoryType`、ToB在根字段 `bizInventoryType` 明确填整数1（仅退件），
不能省略后沿用客户默认值，也不能改为退件优先或使用良品替代；不足时提示用户，不强行建单。
其余参数、预检查、用户授权和回执流程沿用本Skill，不等待仓库、不创建退件处理指令。

使用查询工具读取实际仓库、商品、物流渠道和账号，参数必须先查看对应查询定义。
普通发货按用户指定或用户选择的候选填写；自动分仓由 OMS 执行，客户配置优先。
费用试算需要真实包装长宽高及重量，优先使用查询得到且适用于本单的包装数据；
多 SKU、组合包装不能直接相加边长或猜总包裹重量，没有适用资料时询问用户。
仅展示有效返回的费用、币种和预计时效；没有时效数据就不填写，不承诺送达日期。
不能在自动分仓和普通发货之间擅自切换，也不能替用户选购保险、签名、退货面单或贴标服务。

## 预检查、确认和建单

1. 用 `prepare_oms_outbound_batch(orderType, orders)` 校验并查重。每次最多20单；
   推荐每次5单，以便输出进度并控制调用时间。大表需先预检查全部分组和分批，汇总所有问题。
   在整张表或聊天清单范围内核对参考号是否重复，不能只检查各次工具调用内部的重复。
   `NEEDS_INPUT` 时按中文 `issues` 补充，`ERROR` 时先处理查询错误，尚未执行建单。
2. `BLOCKED`、`EXISTS` 或 `DUPLICATE`：展示重复参考号和已有单号、状态，停止整批，
   由用户决定下一步。不能自动跳过、改号、修改、复用或提交已有订单。
   用户决定排除重复单后，重新预检查剩余清单，再按其授权执行。
3. 展示待执行单数、类型、主要收件信息、SKU数量、发货方式、仓库/渠道或自动分仓规则，
   默认及收费相关选项，并说明默认会直接提交。用户明确同意对应清单后传 `confirmed: true`；
   已有明确授权时不重复询问同一动作，后续改变关键资料或费用选项时重新确认变更。
4. 调用 `create_oms_outbound_batch(orderType, orders, confirmed: true)`，使用预检查后的 `request`。
   服务端会重新校验和查重，逐单执行。创建参数状态0表示仅保存，状态1或省略表示创建并提交；
   创建成功后不再重复建单。OMS OpenAPI 未暴露单独提交草稿的出库接口，已存在草稿不能通过重新创建来提交。
5. 单笔业务失败或 `UNKNOWN` 时按用户选择继续其他订单，汇总时保留前序成功编号。
   `UNKNOWN` 在本批结束后按参考号查询，并通过 `latestOrder` 返回核实结果；不自动重发写请求。
   没有参考号的 ToB 超时单需要用户在 OMS 核实。未查到也不能直接认定创建失败后重建。
6. 执行中发现同参考号订单时停止剩余清单。已执行结果保留，`NOT_EXECUTED` 不代表失败建单；
   展示给用户决定是否继续。重传文件或继续批次时，先核对历史回执及已有订单，不重新发送成功或未确认的单据。

## 发货回执与取消

- 用表格汇总原序号、参考号、OMS单号、本次操作结果、实际业务状态、跟踪号、面单及失败原因。
  `SUCCESS` 是 OMS 确认建单成功，不表示仓库已经拣货或包裹已发货；未知状态保留原码。
- 按需查询 ToC/ToB 列表或详情获取面单和跟踪号；没有数据就展示未查到，不编造回执。
  大表可以把已确认的逐单结果保存为本地 JSON/CSV，保留结果未确认和未执行的单据，方便继续处理。
- 用户要求取消时，先查对应订单并查看 `cancel_oms_toc` 或 `cancel_oms_tob` 定义。
  确认选定单号及取消原因后调用 `cancel_oms_outbound`，沿用 OMS 截单/作废规则。
  ToB 审核通过后或拣货后不扩展取消能力；不以取消请求代替承运商拦截工单，不自动执行待提交订单删除。
- 取消 `UNKNOWN` 时先查询最新订单状态，不直接再次取消。
  仓库截单时间由 OWMS 配置，本期不做时间判断、巡检或提醒；长期跟踪和通知在 Agent 层按客户需要定制。
