# 订单表读取

脚本只使用 Python 3 标准库，无需安装 Excel 库，不访问 OMS。
支持 XLSX、UTF-8/GB18030 CSV；XLS 请先另存为 XLSX。

```bash
python3 scripts/parse_order_sheet.py "订单表.xlsx" --order-type TOC --output "待检查订单.json"
```

相对于 Skill 文件夹运行，或使用脚本的绝对路径。多工作表使用 `--sheet "工作表名"`；
表头不是第一行时使用 `--header-row 2`。可以通过 `--common-json "整批通用参数.json"`
合并用户已提供的通用 OMS 参数；文件内非空资料优先，无默认发货方式。

默认映射 OMS 模板的中文表头和对应接口字段名：序号、发货仓代码、目的国家/地区、
姓名、公司名称、地址1/2、门牌号、邮政编码、城市、州/省、电子邮件、联系电话、
参考号、SKU、数量、生产批次号、产品序列号及平台等。
ToC 还支持自动分仓状态、面单获取方式、物流服务商、物流产品、平台账号、店铺号等；
ToB 还支持出库类型、发货方式、收件仓库代码、发货号及 Code。
其他复杂附件、托盘、贴标及收费字段通过通用参数JSON或在聊天中补充，再交 MCP 校验。

输出 `orders[].request` 是待检查的 OMS 参数，`serialNumber`、`rows` 只用来对应源文件，
不作为接口参数，也不自动变成参考号。同一序号归并全部 SKU；同一字段有两个不同值时
在 `issues` 中标明冲突。普通空白序号行不自动推断归属；显式合并单元格会按其范围展开。

有公式时要求先保存为值，避免用过期公式缓存发货。文本及纯零占位格式保留邮编、SKU、
参考号的前导零；Excel 已丢失的长号码精度不能恢复，需要用户提供原始文本。
脚本不推断任意电商平台名称、国家或渠道代码；用实际接口说明、查询结果和用户资料转换。
`unmappedColumns` 必须核对：模板里的区、错误信息等没有对应建单字段，不能把收件地址
或有业务含义的新字段静默丢弃。脚本 `issues` 未处理完之前不建单。

单笔聊天录单无需此脚本，直接构造一个 `request`；传给 MCP 时用 `orders: [request]`。
