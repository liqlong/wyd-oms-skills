# 修改或删除已有拦截、调查工单

只在用户要求修改或删除包裹拦截、包裹调查工单时读取。参数和状态映射见 [工单说明](work-orders.md)。

## 先核对类型和单据

先查看对应修改或删除操作的 `describe_oms_package_exception_operation`，按类型选择查询：
拦截为 `csc_package_interception_page_query`，调查为 `csc_package_trace_page_query`。
使用 `query_oms`，按服务工单号精确查询时传 `orderNoType4ExactMatch=5`、
`orderNoList4ExactMatch` 为真实服务工单号数组，页码及大小以定义为准。
只给订单号或跟踪号时先查候选并由用户选定，不能当作服务工单号传给修改或删除。

展示最新类型、工单号、关联订单、状态、说明、调查类型及附件，不混用另一个工单类型的接口。
未查到、已删除或查询失败时停止，不用新增接口替代修改，不自动重建删除后的工单。
服务端在当前客户范围内重新查单；具体可修改、删除的状态由OMS校验，不推断所有状态可操作。

## 修改

| 类型 | 工具 | 修改资料 |
| --- | --- | --- |
| 拦截 | `update_oms_package_interception` | `serviceOrderNo`、明确的 `submitFlag`；说明 `remark` 可省略，最多500字符，仅用户明确要求清空时传空字符串 |
| 调查 | `update_oms_package_trace` | `serviceOrderNo`、明确的 `submitFlag`、`traceType`及非空 `remark`（最多500字符） |

调查类型按实时定义的1至6选择，不自行默认类型；用户未要求更改时，将现有类型和说明列入拟保留资料供确认，
不能省略接口必填的类型或说明。修改不是任意字段的局部补丁，不悄悄清空未指定资料。

两类修改附件 `orderFileList` 均可省略或传0至5个，不要求为了修改重新上传至少一个附件。
新增或替换实际文件时使用本Skill的上传能力，核对完整拟提交附件；不擅自丢弃已有附件。
用户明确要求空列表时才传 `[]`，省略、空列表的实际效果按OMS回执及查询核实，不能直接声称已清空。

`submitFlag` 必须明确为1仅保存修改或2修改并提交，没有工具默认值。
只要求修改/保存时使用1；明确要求修改并提交时使用2。展示服务工单号、拟修改资料、附件和保存/提交方式，
沿用用户对本次具体操作的明确授权后，以 `request` 及 `confirmed: true` 调用对应工具。
修改成功不再自动调用草稿提交工具；成功不代表承运商已拦截或完成调查。

## 删除与结果核实

拦截调用 `delete_oms_package_interception`，调查调用 `delete_oms_package_trace`；
参数均为选定的单个 `serviceOrderNo` 和 `confirmed: true`，不需要说明、调查类型、新地址或附件。
先展示删除目标及最新状态，用户明确要求删除该工单才执行；已有具体授权不重复询问，
“查看”“继续”或此前创建、修改授权不能当作删除授权。不额外操作业务订单、原文件或其他类型工单。

`SUCCESS` 表示OMS确认操作成功，`data` 为空仍可成功，回执保留真实工单号和动作。
`ERROR` 展示实际原因，不绕过业务状态校验。`UNKNOWN` 先按同类型工单号核实，不重发修改或删除、不另建新单；
修改核对说明、调查类型、附件及状态，删除仅查询为空不能单独证明本次删除成功，无法确定时明确说明。
